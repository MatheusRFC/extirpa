The leftover search now also covers what Windows itself keeps about a program, and the results come in two steps: first the registry, then files and folders.

## New

- **Two-step leftover window.** Step 1: registry and system items (keys, values, services, scheduled tasks, firewall rules, PATH, packages), with the count of keys and values. Step 2: files and folders, with counts and total size. Each step has its own **Delete checked**; after the registry is cleaned without failures, the window moves on to the files.
- **Analysis before uninstalling.** Right before the program's uninstaller runs, EXTIRPA searches with the program still installed. Whatever that search found and is still the program's after the uninstaller (same name, same path or same content) is added to the leftovers.
- **Windows Installer leftovers** of MSI programs, by product code: the product registration (`Installer\Products`, `Features`, `UpgradeCodes`, `UserData\<user>\Products`, the components only it used, and only its value in shared ones), its `Installer\Folders` entries, the cached package registered as its `LocalPackage`, `C:\Windows\Installer\{code}` and `SourceHash{code}`. After a normal `msiexec /x`, the cache folder and its `Folders` entry are what usually remains; in a forced uninstall the whole registration is offered, so Windows no longer thinks the program is installed.
- **Traces kept under the executable's name:** Prefetch files, crash dumps (`%LOCALAPPDATA%\CrashDumps`), Windows Error Reporting folders, network tracing keys (`Microsoft\Tracing\<exe>_RASAPI32`/`_RASMANCS`), heap-leak diagnosis and DirectInput keys. High confidence when the executable has the program's name; medium for other executables that were in its folder; low for generic names (`unins000`, `setup`, `update`...) or names another installed program also uses.
- Explorer's taskbar usage (FeatureUsage), "new app for this file type" notices, `Compatibility Assistant\Persisted`, `Applications\<program>.exe` keys and dot folders in the user profile (`%USERPROFILE%\.<program>`).

## Fixed

- A file type class that belongs to Windows or another program (`AudioCD`, `DVD`...) where the program only added a verb is no longer offered as a whole key; only the program's verb is. Found while testing this version with VLC; 1.0.x had the same flaw in forced uninstalls of a program still installed.
- The analysis before uninstalling never brings back a value whose content changed (an association the uninstaller handed back to another program) or a PATH entry the uninstaller already removed.

## Protection list

Narrow exceptions for the items above, documented in `SECURITY.md`: only keys named by the program's exact packed product code under the Windows Installer areas and values of `Installer\Folders`; inside the Windows folder, only direct children of `C:\Windows\Installer` named `{code}`, `SourceHash{code}` or `<name>.msi`/`.msp`, and `C:\Windows\Prefetch\NAME.EXE-XXXXXXXX.pf`. The keys that group all products and the rest of the Windows folder stay protected.

## Tested

- 333 core checks and 489 checks of the Windows layer against a simulated registry and disk (Linux, ASan/UBSan), 0 failures. New scenarios: GridCraft (MSI) installed and after `msiexec /x`, with another MSI product, shared components and the Windows Installer cache that must stay; VLC's verb inside Windows' `AudioCD` class; Greenshot, whose name is also its publisher's.
- Clean Windows Server 2025 (GitHub Actions), GridCraft 0.9.0 from its MSI, opened through the Start menu: with the program installed EXTIRPA finds 34 items (1.0.0: 7), including the whole Windows Installer registration. Uninstalled by EXTIRPA, then leftovers deleted: nothing named GridCraft and nothing with its product code is left in `HKCU` or `HKLM\SOFTWARE`, and `C:\Windows\Installer\{code}` is gone.
- 12 real programs installed, opened and removed by EXTIRPA (Notepad++, VLC, KeePass, FileZilla, WinSCP, 7-Zip, Audacity, PuTTY, Everything, SumatraPDF, Greenshot; IrfanView's uninstaller has no silent mode, so it was only scanned). What remained: a DLL loaded by Explorer (WinSCP, scheduled for deletion at restart) and 4 bookkeeping entries Windows keeps after removing a package (Notepad++). The test now also flags any deleted item that existed before the test programs were installed: the only ones were 7-Zip's own key and Start-menu entry, because 7-Zip comes preinstalled on that machine image. Self-test: 23 OK, 0 failures.
- Prefetch is disabled on Windows Server, so Prefetch files were covered only by the simulated tests.
